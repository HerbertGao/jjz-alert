## 目的

本能力定义进京证状态从上游响应到推送文案的呈现契约：解析记录时必须透传上游给出的审核不通过原因，推送正文必须向用户展示上游原文的状态描述与原因，而不是对用户暴露内部状态枚举值。

## 新增需求

### 需求:审核不通过原因透传

系统在解析进京证记录时，必须把上游返回的审核不通过原因原样写入 `JJZStatus.reject_reason`，取值优先级为记录级 `shsbyyms` → 记录级 `shsbyy` → 车辆级 `bnbzyy`。三个字段均缺失或为空时，`reject_reason` 必须为空字符串或 `None`。原因的透传禁止改变状态判定结果，也禁止影响 `error_message`（后者继续只承载系统级与解析级错误）。

#### 场景:记录级原因优先

- **当** 一条进京证记录包含 `shsbyyms="审核未通过，该车辆在京有未处理的交通违法行为。"`，且同一响应中车辆级 `bnbzyy` 另有文本
- **那么** 该记录的 `reject_reason` 必须等于 `shsbyyms` 原文，`status` 必须与该记录 `blzt`/`blztmc`/有效期在本变更前推导出的结果完全一致

#### 场景:回退到记录级备用字段

- **当** 一条进京证记录的 `shsbyyms` 缺失或为空，且 `shsbyy` 非空
- **那么** 该记录的 `reject_reason` 必须等于 `shsbyy` 原文

#### 场景:回退到车辆级原因

- **当** 一条进京证记录的 `shsbyyms` 与 `shsbyy` 均缺失或为空，且所属车辆的 `bnbzyy` 非空
- **那么** 该记录的 `reject_reason` 必须等于该车辆 `bnbzyy` 原文

#### 场景:无车辆记录但存在车辆级原因

- **当** 查询结果中目标车辆存在且 `bnbzyy` 非空，但该车辆的 `bzxx` 为空数组
- **那么** 返回的状态必须仍为 `INVALID`，且 `reject_reason` 必须等于该车辆 `bnbzyy` 原文

#### 场景:无任何原因字段

- **当** `shsbyyms`、`shsbyy`、`bnbzyy` 均缺失或为空
- **那么** `reject_reason` 必须为空，且推送必须保持本变更前的兜底文案

#### 场景:原因透传不影响系统级错误分流

- **当** 一条审核不通过记录的 `reject_reason` 文本中包含 `_is_system_error` 判定的关键词（例如「配置错误」）
- **那么** 系统必须仍然向用户推送该车牌的状态通知，禁止因该原因文本而跳过用户推送

### 需求:审核不通过推送文案

状态为 `INVALID` 时，推送正文的状态文本必须优先使用上游 `blztmc` 原文；`blztmc` 缺失或为空时必须回退到状态枚举值。正文的原因部分必须优先使用 `reject_reason`，为空时必须回退到既有的 `error_message`。本能力要求适用于批量推送与逐车牌推送两条路径。

#### 场景:审核不通过推送展示原文状态与原因

- **当** 某车牌的最新记录 `blzt="4"`、`blztmc="失败(审核不通过)"`、`reject_reason="审核未通过，该车辆在京有未处理的交通违法行为。"`
- **那么** 推送正文必须形如「车牌<显示名>的进京证(<类型>)状态：失败(审核不通过)。审核未通过，该车辆在京有未处理的交通违法行为。」

#### 场景:不再向用户暴露状态枚举值

- **当** 状态为 `INVALID` 且 `blztmc` 非空
- **那么** 推送正文必须不包含 `invalid` 字样

#### 场景:无上游状态描述时保持兜底

- **当** 状态为 `INVALID` 且 `blztmc` 缺失或为空
- **那么** 推送正文的状态文本必须仍为 `status` 枚举值，并继续展示既有 `error_message`（如「未找到匹配车牌的记录」）

#### 场景:其他状态文案不受影响

- **当** 车牌状态为 `VALID` / `EXPIRED` / `PENDING` / `APPROVED_PENDING` / `ERROR`
- **那么** 推送正文必须与本变更前完全一致
