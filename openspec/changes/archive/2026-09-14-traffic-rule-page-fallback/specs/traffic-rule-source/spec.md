## Purpose

在北京交管尾号限行主接口不可用时，继续从官方详情页取得可验证的轮换规则，保证提醒服务能够安全降级而不凭空推断限行尾号。

## ADDED Requirements

### Requirement: 官方页面降级来源

系统 MUST 优先使用现有限行规则缓存和主 JSON 接口；当主接口请求失败、返回非成功状态或无法解析出规则时，系统 MUST 请求北京交管官方限行详情页作为降级来源。

#### Scenario: 主接口正常

- **WHEN** 缓存未命中且主 JSON 接口返回可解析的规则
- **THEN** 系统 MUST 使用主接口规则并且 MUST NOT 请求官方详情页

#### Scenario: 主接口不可用

- **WHEN** 缓存未命中且主 JSON 接口失败、返回错误状态或返回空规则
- **THEN** 系统 MUST 尝试从官方详情页提取规则

#### Scenario: 两个来源都不可用

- **WHEN** 主 JSON 接口和官方详情页都无法提供可解析规则
- **THEN** 系统 MUST 返回现有的无规则/失败结果，并且 MUST NOT 构造未经来源确认的限行尾号

### Requirement: 轮换表规则提取

系统 MUST 从官方详情页的轮换表提取每个日期区间的星期一至星期五尾号映射，并生成区间内可查询的每日规则。系统 MUST 将周末和页面声明的节假日标记为“不限行”，并且对轮换表覆盖范围之外的日期 MUST 返回解析失败而不是猜测规则。

#### Scenario: 提取完整轮换区间

- **WHEN** 官方详情页包含日期起止范围以及星期一至星期五的尾号单元格
- **THEN** 系统 MUST 为该范围内的工作日生成对应尾号规则，并保留日期和限行尾号信息

#### Scenario: 周末和节假日覆盖

- **WHEN** 目标日期是周六、周日或官方页面内嵌节假日清单中的日期
- **THEN** 系统 MUST 返回“不限行”规则

#### Scenario: 页面结构或日期无效

- **WHEN** 轮换表缺少必要列、日期范围无法解析或尾号映射不完整
- **THEN** 系统 MUST 判定页面来源解析失败，并且 MUST NOT 返回部分猜测的规则集

### Requirement: 异步与同步路径一致

系统 MUST 让异步主流程和同步兼容流程使用同一官方页面规则来源，并对相同日期返回等价的限行尾号结果。官方页面成功解析的规则 MUST 复用现有限行缓存格式，以便后续查询优先命中缓存。

#### Scenario: 异步流程使用降级规则

- **WHEN** 异步限行查询触发官方页面降级且目标日期在有效轮换范围内
- **THEN** 系统 MUST 返回该日期对应的官方页面规则，并将规则写入现有限行缓存

#### Scenario: 同步兼容流程使用降级规则

- **WHEN** 同步兼容查询触发官方页面降级且目标日期在有效轮换范围内
- **THEN** 系统 MUST 返回与异步流程相同的尾号结果

#### Scenario: 来源可观测

- **WHEN** 查询使用了官方页面降级来源
- **THEN** 日志或服务状态 MUST 能区分该规则来自官方页面，而不是主 JSON 接口或缓存
